I have a Python function that processes a list of user records and writes
them to a CSV file. It currently loads the entire list into memory before
writing, which is a problem for very large inputs. Here's roughly what it
looks like:

    def export_users(users, path):
        rows = []
        for user in users:
            rows.append({
                "id": user.id,
                "name": user.name,
                "email": user.email,
                "created_at": user.created_at.isoformat(),
            })
        with open(path, "w", newline="") as f:
            writer = csv.DictWriter(f, fieldnames=rows[0].keys())
            writer.writeheader()
            writer.writerows(rows)

Walk me through how you'd refactor this to stream rows to disk instead of
building the full list in memory first, and explain the tradeoffs of your
approach versus the original. Also mention what would change if `users`
were a generator that could only be iterated once, and how you'd handle a
record with a `None` value in one of the fields without crashing the whole
export.
